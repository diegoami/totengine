# First Original dependency capture

Milestone 17 / #197, the rules/resource part of the frozen
[entry contract](scenario-entry-contract.md). This is a separate adapter API;
it activates no profile, initializer, constructor or client route.

The first bounded dependency set is the installed reference Original pack,
identified by byte lengths and SHA-256 content identities. Existing engine
fingerprints remain in the resource manifest; additional SHA-256 rows bind
every captured input, including the selected save. This is a compatibility set,
not an assertion that every official installation or translation has these
bytes. Other sets need their own evidence before this predicate accepts them.

Capture all twelve dependencies directly from the selected installation's
Original directory: Rules.txt, Events.txt, Labels.txt, Describe.txt and the
eight client BMP roles (terrain1, terrain2, units, cities, city, icons, people,
dialog). Case-insensitive duplicates reject. Missing, unreadable or changed
files reject; there is no root/demo/GIF/optional-art fallback in this first
set. Rules and events retain their exact known content, so an unknown event
branch cannot be admitted by a permissive keyword inventory. Lua scripts or
a Lua directory beside the input reject, rather than being silently disabled.

This is an explicit first-set resolution policy, not a new claim about native
custom-scenario lookup. Existing generated and experimental resolution stays
unchanged. Additional files that this policy never selects do not override a
required role. Video/ending assets are deliberately not dependencies of the
already disclosed terminal/text-without-AVI/ending-screens presentation policy.
That omission is recorded explicitly in the capture identity.

Resolve a selected Original SAV, read each input once, and build its parsed
rules/events/text, decoded sheets and identity from those owned buffers. The
opaque capture keeps both raw bytes and the resulting resources immutable.
No later identity call rereads the installation. A revalidation method captures
the selected inputs again and rejects changes before a future confirmation;
it neither replaces a session nor writes/cache-publishes any original bytes.
The future #198 adapter still owns epochs, cancellation and final replacement.

Acceptance covers an installed positive capture, derived metadata reproduction,
and authored missing/changed rules/events/text/art, case ambiguity, path escape,
Lua, root-fallback refusal, retained byte identity after source mutation and
revalidation failures. Public evidence contains only identities/counts/dimensions,
never source assets, save bytes or original text. The private snapshot-cache
lifecycle remains with #198.

Passing this dependency predicate says nothing about SAV framing/records,
human/pending phase, knowledge continuation or an admitted initializer. #362's
record/normalization slice is independently reviewable; it is not a prerequisite
for this adapter work. Native AI/shared-RNG continuation remains outside the
first-profile contract. No native execution or owner acceptance is implied.
