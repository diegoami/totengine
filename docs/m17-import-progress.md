## Next integration

Run the preparation checks together with
`totctl inspect-original-save "$CIVTOT_HOME" Original/Ph_Auto2.SAV`.
The command captures the reference dependencies, checks record relationships
and saved phase, and projects the saved human view from that capture. Its
schema-2 JSON includes the post-city byte count and the event trailer extents.
The same checks drive **Inspect ToT save / scenario** on both clients. The
inspection shows the selected human's saved view counts and the matching
reference evidence or the input error. It leaves the game and saves intact.
The trailer check expects the measured plain single-player prefix and `EVNT`
marker. It uses a 64-record inspection budget and checks string termination
and EOF. Unknown or malformed inputs return an error with the failing check.
The CLI also bounds the signed count in the 340-byte history block before
`EVNT`. The pinned save has zero entries. Native append and reset checks
establish the layout and 12-entry capacity.
For a well-framed trailer, `victory_event` reports whether the measured rule
fields and embedded strings match the installed event block. A matching
definition includes the two halves' saved active and spent marks separately.
A difference produces a diagnostic within the report. Embedded text remains
private.
The `native_resume_trace` report binds the measured startup observations
to the SHA-256 of the captured save and Rules.txt. A different save
can pass record checks and still show a fixture mismatch. An exact match
includes the post-event loader and Rules refresh through the prepared
same-mode return, the first input poll and an idle iteration.
`playable_import` remains false while event field semantics, pending-state,
and knowledge continuation checks are open.
