## Decisions and limitations for the eventual milestone reviewer

The scope is discovery, reviewed design and implementation planning. It does
not deliver a playable client. The HTML prototype executes authored fixtures;
its format is not a production-toolkit decision, checkpoint or native SAV.
The original-AI completion program #117 and external-AI infrastructure remain
after the playable client. Decision 0003's observation boundary is unchanged.

Reference identity is the installed patched executable; unpatched UI
compatibility is unproven. Some input behavior depends on preferences and focus.
The isolated revolution Escape behavior differs from the proposed safe
cancellation; this difference needs owner acceptance. Native imports retaining
the prior picture do not establish complete state preservation. Full slider,
visibility, government, transport, late-space, event/Lua and scenario-start
branches remain explicitly unverified in the inventory/contracts.

Do not mark #107 complete, bump the version or call the milestone from the
existence of this file. Once owner design/scope decisions are recorded and the
accepted decomposition is in the live queue, finish the release notes/version
candidate and follow [milestone-review.md](milestone-review.md). The owner,
not the implementation session, launches the independent milestone review.

## Required delivery surfaces — owner clarification

On 2026-11-06 the owner emphasized "also" and "we need both": the plan must
include a playable browser client **and** a normal standalone desktop client.
This requirement is settled; architecture/toolkit and ordering are still open.
The observer and simulated prototype do not satisfy playable-browser delivery,
and browser delivery does not satisfy desktop delivery. Decomposition and final
human-play acceptance must cover both surfaces, sharing engine/session contracts
where practical and validating launch/input/assets/save-resume per client.

## Architecture audit and concrete delivery review

The [code/dependency audit](ui/client-architecture.md), against `373d418`, traces
the synchronous Game driver, private order log, atomic city/round processing,
observer disclosure, autonomous checkpoint and missing portable asset-decoder
gaps to implementation. It proposes a shared Rust human session, local-hosted
browser presentation and independent native desktop window, with a mandatory
Windows/Linux toolkit feasibility check. No desktop/WASM build is claimed.

The [first-slice packet](ui/client-milestones.md#proposed-first-slice-for-owner-review)
now provides concrete scope, interaction defaults, both-surface delivery and
human/checkpoint acceptance rather than leaving each alternative unselected.
It narrows the first playable slice to freshly generated Original-profile
surface games; original-save/scenario import follows in lifecycle work. Six
prerequisite stories are defined, without assigned releases. The proposed ten
human rounds per surface validate that slice only, not full campaign usability.
