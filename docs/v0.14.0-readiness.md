# v0.14.0 — city production decisions

Release candidate: milestone 12 / #148–#151. Not released or independently
reviewed. Following the explicit request to test the production routes in both
clients, the owner confirmed “great, it works, let us continue” on 2026-11-07.
This supersedes the earlier deferred test; it accepts this production slice. Scope and exclusions:
[city production milestone](ui/city-production-milestone.md).

Both clients show the current item, invested/required/remaining shields and a
current-output estimate. Production drafts show lost/restored shields before
acceptance. Purchase confirms the exact quote and fills the box; the next city
production phase creates the item. Single-city building sales show their refund
and before/after effects, require confirmation and refresh totals immediately.
Insufficient funds, wrong ownership/entity, stale terms, required decisions and
a second sale in the same city turn reject without economic mutation. Palace,
wonders and spaceship components are excluded from ordinary building sales.

The engine owns a captured initial production class/shield budget. The first
accepted switch records it; draft reads/cancel are inert. Returning to the
initial class can restore that budget. Closing/navigation/turn clear it, buying
rebases it, and recorded replay/checkpoints restore it. An active budget reopens
its owning city after load. The map quick picker closes its temporary context
on acceptance, preserving map continuation on reload. Closing a real context
records its end; it does not alter treasury, shields or either RNG. Autonomous
`SetProduction` and the built-in AI policy are unchanged.

## Reproduction

Set `CIVTOT_HOME` to an owned original installation. Native comparisons also
need Unicorn on `PYTHONPATH`:

```sh
python3 tools/city_production_check.py --gold /tmp/city-production.json --vectors /tmp/city-production-vectors.txt
cmp docs/evidence/city-production-v1.json /tmp/city-production.json
cmp docs/evidence/city-production-vectors.txt /tmp/city-production-vectors.txt
make test fmt clippy
cargo test -p engine --test generated_campaign --release -- --include-ignored
TOTENGINE_PRODUCTION_OUT=/tmp/production-fixture cargo test -p totui generated_city_production_fixture -- --ignored
```

Build the adapters with the optional `desktop` feature and appropriate SDL2
link/runtime setup ([environment](environment.md)). Set
`TOTENGINE_PRODUCTION_FIXTURES` to that private fixture directory when running
`tools/check_client_browser.cjs`, `tools/check_client_linux.py` and
`tools/check_client_windows.ps1`. Browser checks also need the host's private
`TOTENGINE_CLIENT_SAVES` directory and Playwright. Existing citizen/selection/
encounter fixture variables enable their separate routes. Never commit the
install, generated installed-resource checkpoints or screenshots.

## Remaining release gates and limits

#151's new both-client production-route human check is accepted by the owner;
v0.13 citizen acceptance was not reused. Independent review is owner-launched
per [milestone review](milestone-review.md). The candidate contains release
notes and the existing 0.14.0 version bump; main takes only review fixes until
the independently reviewed SHA is tagged. The main session prints the review
prompt and does not launch the review.

The native fragments compare prepared arithmetic/accepted field writes, not
entire original dialogs, auxiliary queued-unit caches, notification/refresh
paths or the complete native window lifecycle. Current-output estimates do not
predict future worker/growth/government changes. Unsupported signed/custom-cost
contexts reject explicitly. Bulk sales, full city reports/panels, rates/
government, diplomacy, original saves/scenarios/multiple maps and sustained full
campaign acceptance remain later. Complete original AI and pluggable AI remain
gated behind complete playable-client delivery. Checkpoints bind exactly to
0.14.0 and resource identity; old releases remain needed for their older saves.
