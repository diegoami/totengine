# v0.15.0 — city information panels

In development, milestone 13 / #157–#159; not released, independently reviewed
or owner accepted. Scope: [city information milestone](ui/city-information-milestone.md).
Both browser and ordinary standalone desktop are required. The v0.14 tag and
accepted owner games/previews stay intact.

## Implemented

The shared city workspace now has Info, Support, Improvements and Happy panels.
Info keeps the accepted tile inspector and adds own units present; Support lists
units supported by the city, including their actual shield/settler-food charges.
Improvements lists owned buildings/upkeep and local wonders/expiry; eligible
building rows open the existing quoted sale confirmation. Happy uses five
original-checked normalized stages and omits unchanged rows like the reference.
Panel choice survives city navigation and accepted edits. Inspection/pagination
never creates an engine order or closes the recorded production budget.
Navigation/closing still end that budget according to v0.14 rules. Hidden tile
arrow/Space actions are ignored outside Info; unit lists never wake/move/disband.

The new immutable HumanView city information is own-city/own-unit filtered and
reuses existing support/upkeep/finance/happiness kernels. Normal happiness now
returns the last stage of the same calculation; final arithmetic is unchanged.

## Reproduction

Set `CIVTOT_HOME` to an owned installation; see environment.md for SDL2 linking.
Native stages need external Unicorn on `PYTHONPATH`:

```sh
python3 tools/happiness_stages_check.py --gold /tmp/stages.json --vectors /tmp/stages.txt
cmp docs/evidence/happiness-stages-v1.json /tmp/stages.json
cmp docs/evidence/happiness-stages-vectors.txt /tmp/stages.txt
make test fmt clippy
cargo test -p engine --test generated_campaign --release -- --include-ignored
```

Run the existing ignored citizens, production and encounter fixture authors into
private directories. Create a private input root with `citizens`, `production`
and `encounter` pointing to those current-version outputs, then:

```sh
TOTENGINE_PANEL_INPUTS=/private/input-root TOTENGINE_PANELS_OUT=/private/panels \
  cargo test -p totui generated_city_panels_fixture -- --ignored
```

Pass that output through `TOTENGINE_PANELS_FIXTURES` to each existing browser/
Linux/Windows input checker. The panel helpers normalize the presentation to
Info after load, perform actual recorded inputs, assert the visible city and
selected panel, save/compare every checkpoint, reload and continue. Presentation
state is deliberately separate from gameplay checkpoint contents.
